# Verifying Nox Releases

Nox releases are signed with [Sigstore cosign](https://github.com/sigstore/cosign)
(keyless) and carry [SLSA Level 3 provenance](https://slsa.dev/). Every command
on this page is run against a real release before the page changes; if one
fails for you, that is a bug — please report it.

## Prerequisites

```bash
brew install cosign        # or: go install github.com/sigstore/cosign/v2/cmd/cosign@latest
go install github.com/slsa-framework/slsa-verifier/v2/cli/slsa-verifier@latest
```

Set the release you are verifying once; every command below uses it.

```bash
VERSION=1.38.2
```

## The signing identity

Every signature below names the workflow that produced it, **at the release
tag**. Verify against that exact identity rather than a pattern: a pattern
accepts a signature from any workflow or ref in the repository, and the exact
form accepts only the release workflow run for this tag.

```bash
IDENTITY="https://github.com/Nox-HQ/nox/.github/workflows/release.yml@refs/tags/v${VERSION}"
ISSUER="https://token.actions.githubusercontent.com"
```

The organisation is `Nox-HQ`, and the match is case-sensitive. Earlier
versions of this page used `nox-hq`, which matched no signature at all.

## 1. Checksums

Each release publishes `checksums.txt` and its cosign bundle,
`checksums.txt.sig.bundle`.

```bash
mkdir -p /tmp/nox-verify && cd /tmp/nox-verify
gh release download "v${VERSION}" --repo Nox-HQ/nox --clobber \
  --pattern 'checksums.txt' --pattern 'checksums.txt.sig.bundle' \
  --pattern "nox_${VERSION}_linux_amd64.tar.gz"

cosign verify-blob checksums.txt \
  --bundle checksums.txt.sig.bundle \
  --certificate-identity "$IDENTITY" \
  --certificate-oidc-issuer "$ISSUER"

sha256sum -c checksums.txt --ignore-missing   # macOS: shasum -a 256 -c checksums.txt --ignore-missing
```

## 2. SLSA provenance

```bash
gh release download "v${VERSION}" --repo Nox-HQ/nox --clobber --pattern '*.intoto.jsonl'

slsa-verifier verify-artifact "nox_${VERSION}_linux_amd64.tar.gz" \
  --provenance-path multiple.intoto.jsonl \
  --source-uri github.com/Nox-HQ/nox \
  --source-tag "v${VERSION}"
```

`--source-tag` is the part that ties the binary to the release rather than
merely to the repository. It verifies for **v0.10.2 and every later release**.

- v1.38.2 onward: the attestation is generated by the release itself, and the
  release workflow runs this exact check before it finishes.
- v0.10.2 – v1.38.1: these originally carried attestations recording
  `refs/heads/main`, so `--source-tag` failed for all of them. They were
  re-attested on their own tags on 2026-09-19.
- v0.2.0 – v0.10.1: no attestation verifies against the tag, and none can be
  added truthfully; each of those release pages says so.

## 3. Container image

```bash
cosign verify "ghcr.io/nox-hq/nox:${VERSION}" \
  --certificate-identity "$IDENTITY" \
  --certificate-oidc-issuer "$ISSUER"
```

Pin by version, as above. `:latest` is signed too, but its tag moves, so there
is no single identity to verify it against.

## What this establishes

- **Checksums signature** — `checksums.txt` was produced by the release
  workflow run for this tag, and has not been altered since.
- **Provenance** — each archive was built by that workflow from the tagged
  commit, meeting SLSA Build Level 3.
- **Container signature** — the image was built and pushed by the release
  workflow run for this tag.
